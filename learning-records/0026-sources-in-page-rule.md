# 内容来源规则：页面内底部列出来源（LR-0026）

**Status**: active — 硬性课程要求（从第 14 课起）

## 学到的

学员要求：「增加课程要求，内容来源要在课后列出来」。

排查现状：16 个课程页面（13 主线 + 5 sup）<strong>一个都没有</strong>来源区块——我一直只在对话回复里给 Sources markdown 链接，页面本身没写。学员看课时无法直接核对来源，违背了 LR-0008（LoRa SF 凭记忆出错）教训确立的"查证可追溯"原则。

## 决策（已与学员确认）

- **来源位置**：每个课程 HTML 页面内底部（lesson-foot 区块里或之后）加「内容来源」小节，列出本课引用的标准/文档/博客/论文（标题 + URL）。
- **回溯范围**：<strong>只从第 14 课起强制</strong>。已写的 1–13 课 + sup-0001~0005 不回溯（它们的来源在对话回复 + learning-records 里有，学员没要求重做）。
- **格式**：精简列表，每条一行，`[标题 — 来源] URL`。不展开摘要（摘要在课正文里）。

## 为什么重要

1. **可追溯**：学员看课时能直接点链接核对，不用回翻对话。延续 LR-0008 教训——每个技术点都能追到一手来源。
2. **学术规范**：内容有来源是知识载体的基本要求，尤其涉及具体数值/公式时（延续 LR-0016 关于 RF 数值必须查一手来源的警示）。
3. **可信度**：让学员知道"这不是 AI 凭记忆编的，是有依据的"，降低 LR-0008 类错误的风险。

## 模板（供后续新课使用）

在 lesson-foot 的 ask-prompt 之后加：

```html
<h2>内容来源</h2>
<ul class="sources-list">
  <li><a href="URL">标题 — 来源/作者</a></li>
  ...
</ul>
```

每课 5-10 条：IEEE 标准条款、权威博客（mrncciew/howiwifi/wifisharks）、学术论文、芯片厂商文档、RFC。
