漫游与 Fast Transition —— 换 AP 不掉线是怎么做到的

这是路线图第 6 步（连接维护）挂账已久的缺口。第 7 课讲了 STA（站点）怎么连上一个 AP（接入点），但真实世界 STA 是移动的：拿着手机从客厅走到卧室，信号变差，得换到更近的 AP——漫游 (Roaming)。朴素的做法是"断开重连"，那要几百毫秒、语音/视频直接断流。这课讲漫游的完整拼图：802.11r（快换）、802.11k（邻居报告）、802.11v（网络指路）。

支点：漫游 = 决策 + 执行，慢在执行

本课支点 / Core Insight

漫游分两半：决策（什么时候走、走去哪——由 STA（站点）自己说了算，Wi-Fi 没有基站指挥）和执行（在新 AP（接入点）上重建连接）。慢就慢在执行：朴素漫游要在新 AP 上把第 7/9 课的流程整个重来一遍——扫描、认证、关联、完整 4-Way Handshake（四次握手）、再拿组播密钥。其中 4-Way（EAPOL（局域网上的 EAP）四帧往返）动辄上百毫秒，语音呼叫早就断了。

802.11r 的核心思路：如果新 AP 和老 AP 认识（同一个 Mobility Domain（移动域）），密钥可以提前算好摊给所有 AP，漫游时只做一次轻量握手——把几百毫秒压到几十毫秒以内。

① 基线：朴素漫游有多慢

朴素漫游 (无任何优化) 的完整开销: STA ──→ 老AP ──→ 新AP ──→ 新AP ──→ 新AP 1. 发现要走了 2. 扫描找邻居 (被动=每信道听 Beacon≥100ms! (RSSI 掉阈值) 主动=每信道发 Probe 等≈10-30ms, ×十几个信道) 3. Authentication (2 帧) 4. Reassociation Request/Response (2 帧) 5. 完整 4-Way Handshake (第 9 课, EAPOL ×4 往返) 6. Group Key Handshake (GTK) 7. 恢复数据 典型总计: 300-800ms → 语音(要求<50ms)断, 视频卡顿, TCP 超时重传

注意第 2 步扫描：STA 要离开当前信道去逐个听/探测其他信道，本身就是几百毫秒的"失联"。802.11k 解决的就是这一步。

② 802.11k RRM（无线资源管理）：AP（接入点）告诉你邻居在哪

802.11k = Radio Resource Measurement，一套"测量与报告"框架。漫游相关的核心是 Neighbor Report（邻居报告）：

STA → AP: Neighbor Report Request "附近有哪些 AP?" AP → STA: Neighbor Report Response 一张邻居清单: ┌──────────────────────────────────────────────┐ │ BSSID 信道 频段 能力(11r/11v/...) │ │ aa:bb:..:01 36 5G 11r+11v │ │ aa:bb:..:02 52 5G 11r │ ← STA 只需扫这几个 │ aa:bb:..:03 1 2.4G - │ └──────────────────────────────────────────────┘ 扫描范围从"全部信道"缩到"清单上的三四个" → 扫描时间砍 80%+

AP（接入点）怎么知道邻居？企业 AP 之间有有线侧的通信（或者自己做邻居扫描）。802.11k 还定义了 Beacon（信标帧）测量、信道负载报告等——都是给 STA 的漫游决策喂料。

③ 802.11v：网络反过来指挥 STA

802.11v = BSS Transition Management（BSS 过渡管理）。11k 是"STA（站点）问、AP（接入点）答"，11v 是 "AP 主动建议"：

  • BSS Transition Request（BSS 过渡请求）：AP 觉得你该走了（负载均衡、信道要关、你信号太差影响别人），主动发帧建议 STA（站点）漫游到指定 BSSID（基本服务集标识）列表。STA 可以听也可以不听——最终决定权仍在 STA。
  • 还附带一些网络管理杂项：多 BSSID 集合通告（6GHz 用它代替被动扫描）、休眠时间协商等。

k + v 合起来把"决策"这一半打磨好：STA（站点）知道邻居在哪（少扫）、网络能给建议（少猜）。剩下的硬骨头是"执行"——密钥。

④ 802.11r FT（快速转换）：快就快在密钥不用现算

回顾第 9 课密钥层级：PSK（预共享密钥）/802.1X → PMK（成对主密钥）→ 每次关联做 4-Way（四次握手）算出 PTK（成对临时密钥）。慢的根源是 PMK→PTK 的握手必须每次现场做。802.11r (Fast BSS Transition, Wi-Fi 联盟叫 802.11r / Passpoint 里的 "FT") 重构了层级：

普通 WPA2 (第 9 课): 802.11r FT 密钥层级: PSK/802.1X PSK/802.1X ↓ (每次关联) ↓ (只在初始关联时做一次) PMK ──── 4-Way ────→ PTK PMK-R0 (存在 R0KH: 通常=首个AP/控制器) (每次漫游都重来!) ↓ (派发) PMK-R1 (预摊/按需发给所有 AP 的 R1KH) ↓ (漫游时一次轻量握手) PTK (只需 SNonce/ANonce 2 帧往返) MDIE (Mobility Domain IE): AP 在 Beacon 里通告 "我们是一个家族, domain id = X" R0KH/R1KH = Key Holder, AP 之间(或经控制器)用有线分发 PMK-R1

漫游时发生什么：STA（站点）认出新 AP（接入点）的 Beacon（信标帧）里有相同的 MDIE（移动域信息元素，同一家族），直接发 FT Authentication Request，里面带上 SNonce 和 R0KH 标识（新 AP 凭它取到 PMK-R1）。新 AP 拿着自己手里的 PMK-R1 现算 PTK，回一帧带 ANonce 的 Authentication Response——两帧搞定密钥，原来的 4-Way 整个消失。随后的 Reassociation Request/Response（重关联请求/响应）只带 MIC（消息完整性码）确认，GTK（组临时密钥）也随 Reassociation Response 一起带上（又省两帧）。

两种漫游方式：

方式流程时延适用
Over-the-Air STA 直接和新 AP 做 FT 认证+重关联（无线口上完成） ~20-50ms 绝大多数场景，消费级也支持
Over-the-DS STA 先通过老 AP（当前连接）转发 FT 请求给新 AP，再切过去 相近 切换前经老 AP 转发不断流，但实现复杂、用得少
优化阶梯全览

把三个修正案叠起来，现代漫游的完整时间线：

  • 决策快：11k Neighbor Report 缩小扫描范围 + 11v 网络主动建议 → 扫描从几百 ms 降到几十 ms
  • 执行快：11r FT 两帧握手替代 4-Way + GTK（组临时密钥）随带 → 认证关联从 100ms+ 降到 ~20ms
  • 总量：朴素 300-800ms → 11k/v/r 全开 <50ms，语音无忧

顺带一提更早的优化：PMK Caching (OKC, Opportunistic Key Caching，机会性密钥缓存)——11r 之前的方案，STA 漫游回"连过的 AP"时复用缓存的 PMK（成对主密钥）跳过 802.1X。仍要做 4-Way，但省掉了最慢的 EAP（可扩展认证协议）认证。11r 是它的彻底版。

⑤ 漫游决策：STA 怎么判断"该走了"

决策没有标准答案（协议不管），典型策略：

  • 信号阈值：当前 AP（接入点）RSSI（接收信号强度指示）掉到阈值（如 -70dBm）以下，触发扫描邻居。
  • 滞后 (Hysteresis)：新 AP 必须比老 AP 好 若干 dB（如 6-8dB）才切——防止在两个 AP 信号相近的边界上来回横跳（ping-pong 漫游）。
  • 负载/重传因素：信号还行但 PER（包错误率）高（AP 太忙），也该走。高级固件会综合丢包率、重传率、负载。
  • 粘性客户端 (Sticky Client) 问题：很多 STA（站点）策略保守，信号烂到 -80dBm 还死赖在老 AP 上，拖垮自己和小区。11v 的主动建议就是给网络"劝退"这类 STA 的手段。

对驱动栈：漫游落代码哪里

对驱动重要 / For Driver Stack

漫游在 Linux 栈的落点（对照 sup-0001 的分层）：

  • 决策在 wpa_supplicant：bgscan 模块（背景扫描）+ roaming 策略。阈值扫描 (bgscan simple: 信号差时提高扫描频率) 是常见配置。
  • SoftMAC（软件 MAC）执行在 mac80211：ieee80211_mgd_assoc（重关联走同一状态机）；11r 的 FT 帧处理在 mlme.c + wpa_supplicant ft.c（FT 协议主体其实跑在 supplicant，因为它管密钥）。
  • FullMAC（全 MAC）漫游在固件：固件自己扫描、决策、执行漫游，驱动只收 roam 事件上报。手机芯片几乎都是这派——固件工程师写的就是这块：扫描调度、候选排序、FT 握手时序、漫游失败回退。
  • 调试：wpa_cli signal_poll 看当前 RSSI（接收信号强度指示）；iw dev wlan0 link；抓包看 Reassoc Request 里的 Mobility Domain IE / FTIE（快速转换信息元素）是否出现——没有就说明 11r 没协商上，走的是慢路径。
  • 常见 bug：ping-pong 漫游（滞后阈值太小）；11r 协商失败静默回退 4-Way（STA（站点）和 AP（接入点）能力位/MDIE（移动域信息元素）不匹配）；漫游到 11r 不兼容的 AP 导致掉线；扫描期间上层业务未感知导致报错。

自检：漫游吃透了吗

这课的钉子：漫游 = 快决策 + 快执行

学完这课，你脑子里应该有：

  1. 漫游两半：决策（STA 自己定，无基站指挥）+ 执行（重建连接）；朴素执行要扫描+重关联+完整 4-Way（四次握手），300-800ms
  2. 11k：Neighbor Report（邻居报告）给邻居清单，扫描范围大缩
  3. 11v：AP 主动 BSS Transition Request（BSS 过渡请求）劝 STA 走（治粘性客户端）
  4. 11r：PMK-R0/R1（两级密钥缓存）密钥层级预摊，漫游两帧出 PTK（成对临时密钥），4-Way 消失；MDIE（移动域信息元素）认家族；Over-the-Air vs Over-the-DS
  5. 决策要点：RSSI（接收信号强度指示）阈值 + 滞后防 ping-pong；OKC 是 11r 前的过渡方案

你现在能做的：

  • 解释"打电话走两步就断"的原因（朴素漫游 4-Way 太慢，>50ms 语音就断）
  • 抓包看 Reassoc 请求里的 MDIE/FTIE（快速转换信息元素），判断 11r 有没有协商上
  • 设计漫游决策策略（阈值 + 滞后 + 负载）并知道 ping-pong 怎么防
  • 说出 FullMAC 固件里漫游模块要做的四件事：扫描调度、候选排序、FT 握手、失败回退
