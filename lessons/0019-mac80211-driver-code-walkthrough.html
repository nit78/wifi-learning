mac80211 代码导读 —— 驱动框架怎么搭

这是你转岗使命的正主：前面 18 课攒的协议知识，这课开始落进 Linux 内核代码。补充课 1 讲过"帧在四层软件栈里怎么流"（架构层），这课往下钻一层——函数与结构体层：一个 Wi-Fi 驱动到底要写哪些函数、注册什么、数据从哪进从哪出。好消息：你写过蓝牙驱动，这里的套路你全部见过，只是换了名字。

支点：mac80211 是"半成品协议栈"，你只填一张回调表

本课支点 / Core Insight

Linux 把 802.11 协议栈劈成两半：框架（mac80211）包揽"协议"——管理帧解析、关联状态机（第 7 课）、加密握手后的密钥装载（第 9 课）、聚合会话（第 12 课）、速率控制统计（第 18 课）；驱动只做"硬件抽象"——把帧搬进搬出芯片、配置寄存器。

两者的契约就是一张函数指针表 struct ieee80211_ops（驱动操作回调表）。这和你写蓝牙驱动时注册 hci_dev（主机控制器接口设备）、填 .send/.open 回调、用 hci_recv_frame() 送帧上来，是一模一样的肌肉记忆。

① 鸟瞰：三个子系统 + 你的驱动

用户态: iw / wpa_supplicant (认证器客户端) ← 第 20 课的主角们 │ nl80211 (Netlink 用户态接口, 多播/单播消息) ▼ cfg80211 (配置面: 扫描结果/ Regulatory 法规/ 接口管理) │ ▼ mac80211 (数据面: 协议主体 — 管理帧/加密/聚合/速率控制) │ ieee80211_ops 回调表 ←—— 你的驱动要实现的全部 ▼ 你的驱动 (mt76 / ath11k / iwlwifi ...) │ 寄存器 + DMA (直接内存访问) / 或 MCU (微控制器) 消息 ▼ 硬件

一句话分工：cfg80211（配置子系统）管"配置"（扫描、法规、接口增删，通过 nl80211 消息和用户态对话）；mac80211（介质访问控制子系统）管"数据与协议"（帧的加工与流动）；驱动管"硬件"。SoftMAC（软件介质访问控制）芯片走完整条路；FullMAC（全硬件介质访问控制）芯片则由固件包掉 mac80211 的大部分活，驱动只剩 cfg80211 + 固件通道——补充课 1 详述过这个分野，不重复。

② 驱动注册三步曲

任何 SoftMAC 驱动的 probe()（总线探测函数，PCIe（高速外设互联）热插拔或平台设备枚举时被调）都长这个样子：

/* 简化示意：结构来自内核 Documentation，字段名以 include/net/mac80211.h 为准 */ static int my_wifi_probe(struct platform_device *pdev) { struct my_priv *priv; /* 第 1 步：分配 hw 对象（框架的"设备代表"），绑定 ops 回调表 */ hw = ieee80211_alloc_hw(sizeof(*priv), &my_wifi_ops); if (IS_ERR(hw)) return PTR_ERR(hw); priv = hw->priv; /* 框架替你分配的驱动私有数据 */ /* 第 2 步：描述硬件能力 —— 你在前 18 课学的每个特性都在这声明 */ hw->queues = 4; /* 硬件队列数：对应 EDCA 的 4 个 AC（接入类别）→ 第 11 课 */ hw->max_rates = 4; /* 重传链长度 → 第 18 课 retry chain */ /* ... 填 band（频段）/ 支持的 MCS（调制与编码方案）/ iftype（接口类型）… */ /* 第 3 步：注册进框架 —— 从此框架会按需调你的回调 */ ret = ieee80211_register_hw(hw); if (ret) goto err_free; /* 失败路径：ieee80211_free_hw(hw) */ return 0; }

三个动作记住顺序：alloc（分配）→ 填能力 → register（注册）。struct ieee80211_hw（硬件抽象对象）是框架视角的"你的网卡"，里面内嵌 wiphy（无线物理设备对象，cfg80211 的句柄）和给驱动留的 priv 私有区——这个"对象里塞私有数据"的手法，和蓝牙 hci_dev 如出一辙。

③ ieee80211_ops：唯一要填的"菜单"

回调几十个，但没有一个驱动全填——不填的留 NULL（空指针），框架走默认/软件路径。按职责分组看高频核心：

看出味道了吗：每张课学过的协议机制，最终都落到某个回调里"通知驱动"。这就是协议课和驱动课的接口面——面试问"四次握手之后内核做了什么"，答案链条是：wpa_supplicant（认证器客户端）算出 PTK → 经 nl80211 交给内核 → .set_key 进驱动 → 硬件装密钥。

④ 两条数据路径：一帧的完整旅程

驱动工程师的日常 90% 在这两条路上。TX（发送）方向：

TX 发送路径（框架 → 驱动）: 应用数据 │ 网络栈 ndo_start_xmit (网卡发送入口) ▼ mac80211: 选 AC（接入类别）队列 (第11课 EDCA) → 速率控制 get_rate() 选 MCS (第18课) → 加密标志 (硬件加密? 带上 key idx 第9课) ▼ .tx(hw, skb, control) ← 驱动拿到帧: 入 DMA 环 / 发寄存器 ▼ 硬件发出, 产生完成中断 ▼ ieee80211_tx_status(hw, skb) ← 驱动回报: 成功/失败 + 实际用的速率 └→ 喂速率控制 tx_status() 统计 (第18课闭环) / 重传决策

RX（接收）方向则反过来，驱动要先"打扮"好每个帧再交框架：

RX 接收路径（驱动 → 框架）: 硬中断/NAPI (中断+轮询混合收包) 收到帧 ▼ 驱动解析硬件 RX 描述符: 信号强度/速率/是否已硬件解密 ▼ 填 skb->cb 里的 struct ieee80211_rx_status (接收元数据): .band 频段 .freq 频率 .signal 信号(dBm 分贝毫瓦) .rate_idx 速率 .flag |= RX_FLAG_DECRYPTED (硬件已解密) ▼ ieee80211_rx() 交框架 (NAPI/软中断上下文直接调; 进程上下文用 ieee80211_rx_ni 变体) ▼ mac80211: A-MPDU (聚合介质访问控制协议数据单元) 重排序 → rx handlers (接收处理链) ├─ 数据帧 → 递给网络栈 → 应用 └─ 管理帧 → 关联状态机(第7课) / 经 cfg80211 转发用户态 wpa_supplicant (第9课)

注意职责边界：驱动不解析管理帧（那是框架的活），只如实上报"这帧怎么收来的"（元数据）。唯一要小心的坑：skb（套接字缓冲区，内核的帧容器）的 cb（控制块）区在收发两个方向被框架塞了不同的结构（RX 是 ieee80211_rx_status，TX 完成时是 ieee80211_tx_info）——驱动碰 cb 前必须看清方向，这是新手驱动最常见的崩溃源之一。

⑤ 看一个真实驱动：mt76（联发科家族）

理论落地。mt76 是最推荐的入门阅读对象：现代、在主线内核、同时覆盖 PCIe（高速外设互联）/USB/SDIO（安全数字输入输出）三种总线、还带片上 MCU（微控制器）消息通道——一份代码看全所有总线形态。以 Wi-Fi 6 芯片 mt7915 为例：

drivers/net/wireless/mediatek/mt76/ ← 内核主线真实路径 ├── dma.c util.c mac80211.c 芯片无关共享层: DMA 环/公共工具 ├── pci.c usb.c sdio.c 三种总线的接入抽象 └── mt7915/ 具体芯片一族 ├── main.c probe 探测 + ieee80211_ops 表 + 回调实现 ├── mac.c 收发数据路径: 中断/描述符/寄存器时序 ├── dma.c 环形缓冲区管理 (帧在内存与硬件间搬运) ├── mcu.c 与片上 MCU(固件) 的消息通道 — 一半协议跑在固件里 ├── init.c eeprom.c 初始化 / EEPROM (电可擦写存储器) 校准数据 ├── mmio.c pci.c soc.c 内存映射 IO / PCIe / 片上系统接入 └── debugfs.c 调试接口 — 第 20 课的现场

两个观察：① "共享层 + 芯片子目录"是 Wi-Fi 驱动的通用组织法（ath（高通 Atheros 家族）系列、iwlwifi（英特尔无线）同款），因为一个厂商家族的芯片 80% 代码可复用；② 现代驱动是"寄存器 + MCU 消息"混合体——数据面走寄存器/DMA（直接内存访问，延迟敏感），配置面（扫描、功率控制、固件表）打包成消息发给片上 MCU。你在蓝牙里写的 HCI（主机控制器接口）命令包，和这里的 MCU 消息，扮演的角色几乎相同。

⑥ 蓝牙驱动对照桥：你已经会的那套直接平移

把两边的"骨架动作"对齐——这张表是本课最值得收藏的东西：

蓝牙（你熟的）Wi-Fi / mac80211（新家）骨架动作
hci_alloc_dev() → hci_register_dev()ieee80211_alloc_hw() → ieee80211_register_hw()分配设备对象 + 注册进栈
hdev->open / hdev->close.start / .stop开/关硬件
hdev->send(skb).tx(hw, skb, control)栈把帧交给驱动发
hci_recv_frame(hdev, skb)ieee80211_rx(hw, skb)驱动把收到的帧交回栈
hdev->flush.flush丢弃在途帧
—（LMP（链路管理协议）在控制器固件里，host 不可见）.set_key / .ampdu_action / .sta_state协议事件通知驱动（框架管协议但硬件要配合）
skb 承载 HCI 包skb 承载 802.11 帧（cb 里塞元数据）同一套内核帧容器约定

最后一行是本质差异：蓝牙把 LMP（链路管理协议）等时序协议整个关进控制器固件，host 驱动真的只是"搬运工"；Wi-Fi 因为 CSMA/CA（载波侦听多址接入/碰撞避免，第 5 课）和聚合、加密联动都要 host 参与决策，框架和硬件之间才有这么多协议级回调。驱动要理解的协议深度，Wi-Fi 远大于蓝牙——这正是你上前 18 课的原因。

对驱动栈：入职第一周任务清单

对驱动重要 / For Driver Stack

拿到一份 Wi-Fi 驱动代码库，按这五步建立地图：

  • ① 找 ops 表：grep（全局搜索）ieee80211_ops —— 它是驱动功能的"目录页"，扫一眼就知道这驱动支持什么（有没有 .hw_scan 硬扫？.ampdu_action 聚合？）。
  • ② 跟一条 TX 帧：从 .tx 回调向下追到 DMA 环入队，再追完成中断到 ieee80211_tx_status()。
  • ③ 跟一条 RX 帧：从中断/NAPI 收包追到 ieee80211_rx()，看清 ieee80211_rx_status（接收元数据）每个字段从哪个硬件描述符来。
  • ④ 对照框架目录：net/mac80211/ 下的 rx.c（接收处理链）、tx.c（发送处理）、sta_info.c（站点表，RCU（读-复制更新）无锁保护的重点）、key.c（密钥）、rc/rc80211_minstrel_ht.c（第 18 课的速率控制）——遇到问题先定位"是框架层还是驱动层"。
  • ⑤ 会遇到的黑话：txq/txqi（每站点发送队列，airtime（空口时间）公平调度的单位）、chanctx（信道上下文，多接口共享射频的资源抽象）、offchannel（离信道操作，扫描/保护帧时暂离主信道）。

典型 bug 高发区：cb 控制块方向搞混、RX（接收）元数据漏填或单位错（signal 用错 dBm（分贝毫瓦）/内部值）、.set_key 和加密标志不一致导致"关联成功但一个数据帧都解不开"、ampdu_action（聚合动作）时序没处理好导致聚合永远建不起来。

自检：mac80211 框架吃透了吗

这课的钉子：一张 ops 表 + 两条数据路径

学完这课，你脑子里应该有：

  1. 分层契约：cfg80211（配置面）/nl80211（用户态接口）/mac80211（协议数据面）三件套，驱动=硬件抽象，契约=一张 ieee80211_ops 回调表
  2. 注册三步曲：ieee80211_alloc_hw → 填能力 → ieee80211_register_hw；能力声明覆盖前 18 课每个特性（队列=AC、MCS、聚合）
  3. 两条路径：TX = .tx 回调进驱动 → 完成后 ieee80211_tx_status 回报喂速率控制；RX = 填 ieee80211_rx_status 元数据 → ieee80211_rx 交框架，管理帧解析在框架
  4. 真实组织法：mt76 = 共享层（总线/DMA）+ 芯片子目录（main/mac/dma/mcu），现代驱动 = 寄存器 + MCU 消息混合体
  5. 蓝牙平移表：alloc/register、.send↔.tx、hci_recv_frame↔ieee80211_rx 一一对齐；差异 = Wi-Fi 驱动要理解更深的协议（.set_key/.ampdu_action/.sta_state）

你现在能做的：

  • 打开任意 Wi-Fi 驱动，先 grep ieee80211_ops 三分钟建立功能地图
  • 跟着一次握手抓包，说出密钥从 wpa_supplicant 到硬件加密引擎的完整链条
  • 解释为什么 Wi-Fi 驱动的协议深度要求远高于蓝牙驱动（协议回调的数量差）
  • 在内核源码树里定位 net/mac80211/ 与 drivers/net/wireless/ 的对应模块
