信道绑定与频谱划分 —— 吞吐主线的地基

第 12 课讲了聚合（一次发一大包）、第 14 课讲了 OFDMA（正交频分多址，把信道切给多设备）——但有一块地基一直没铺：信道本身有多宽、怎么来的。Wi-Fi 的 "20/40/80/160 MHz" 不是天上掉下来的，是把相邻的 20MHz 信道绑在一起用。这课讲清楚：频谱怎么划分、信道怎么绑定、绑宽了付出什么代价。这是吞吐主线的最后一块拼图。

支点：一切从 20MHz 说起

本课支点 / Core Insight

OFDM（正交频分复用，第 2 课）的基本单位是 20MHz 信道：64 个 312.5kHz 子载波（11n/ac），或 256 个 78.125kHz 子载波（11ax，第 15 课）。要更高吞吐，最粗暴的一招是把两个相邻 20MHz 绑成一个 40MHz——子载波翻倍，理论速率直接翻倍。这就是信道绑定 (Channel Bonding)。

但天下没有免费的带宽：绑得越宽，噪声底越高（第 4 课：带宽翻倍，噪声底 +3dB）、需要空闲的频谱越多、被邻居干扰的面越大。信道绑定是"用干扰容忍度换吞吐"的交易。

① 频谱划分：2.4 / 5 / 6 GHz 三个战场

先看地有多大。Wi-Fi 有三个频段，性格完全不同：

频段范围20MHz 信道数特点
2.4 GHz 2.400–2.4835 GHz 11/13 个（互重叠！） 传播远、穿墙好；但只有 3 个不重叠信道（1/6/11），且与蓝牙/微波炉共处
5 GHz ~5.150–5.895 GHz（各国不同） 20+ 个 带宽大户；部分信道要 DFS（雷达避让）；穿墙衰减大
6 GHz (Wi-Fi 6E/7) 5.925–7.125 GHz ~59 个（含 7 个 160MHz） 2020 年开放，只许 Wi-Fi 6 及以上进入（无老协议拖累，无需等待).
2.4 GHz 的经典困境 —— 信道互相重叠 (每个 20MHz, 间隔只有 5MHz): 1 6 11 ├──20MHz──┤ ├──20MHz──┤ ├──20MHz──┤ 1/6/11 互相不重叠 → 唯一靠谱的三兄弟 选 3 和 6? 部分重叠 → 互相干扰且解不出来 → 比同信道更糟 5 GHz (编号规则: 信道号 ×5 = 中心频率 MHz 偏移, 如 ch36=5180): ch36 ─ ch40 ─ ch44 ─ ch48 ─ ch52* ─ ch56* ─ ch60* ─ ch64* ... *=DFS 信道: 先听雷达(CAC 60s), 听到就让路

DFS（动态频率选择）：5GHz 的部分频段与气象/军用雷达共用，法规要求 AP（接入点）上电先做 CAC（信道可用性检查，通常 60 秒）确认没雷达才能用；用着用着检测到雷达脉冲必须立刻让路（切换信道）。这是企业网和调试时常见的"AP 突然换信道了"的原因。

② 40MHz：主信道 + 辅信道

802.11n (Wi-Fi 4) 引入信道绑定。一个 40MHz 由主 20MHz (Primary 20MHz) + 辅 20MHz (Secondary 20MHz) 组成：

40 MHz = 主 20 + 辅 20 ┌───────────────────────────┬───────────────────────────┐ │ Primary 20MHz (ch36) │ Secondary 20MHz (ch40) │ │ 老设备在这里收发 20MHz 帧 │ 只在绑定传输时才用 │ │ Beacon/管理帧都走主信道 │ 必须空闲才能绑着发 │ └───────────────────────────┴───────────────────────────┘ 关键规则: 1. 主信道永远承载信令 —— Beacon、关联、老设备的 20MHz 帧全在主信道 2. 发 40MHz 帧前, 主+辅两个 20MHz 都必须 CCA 空闲 (辅信道不用 DIFS/退避那套, 只需能量检测: 次信道空闲 ≥ 一个 CCA 时隙) 3. 40MHz 帧的 前导码只在主 20MHz 上重复一份在辅信道 → 老 20MHz 设备听到也能正确设置 NAV, 不去撞辅信道

为什么这么设计：向后兼容。11n AP（接入点）带着一群 11a/b/g 老设备时，老设备只在主信道说话（它们不知道 40MHz 的存在）；靠主信道上的前导码重复，老设备也能"听到"40MHz 传输并退避。代价是一个 20MHz 老设备就能拖累整个 40MHz 小区——共存机制（20/40 Coexistence、Forty MHz Intolerant 位）允许老设备宣布"别绑了"，AP 退回 20MHz。2.4GHz 上这个机制几乎总是触发，所以 2.4GHz 实战中别指望 40MHz。

③ 80/160/80+80：VHT 的扩张 + 绑定的代价

802.11ac (Wi-Fi 5) 把绑定推向 80/160MHz。结构是递归的：80 = 主 20 + 辅 20 + 辅 40；160 = 两个 80MHz 相邻绑定，或 80+80（两个不相邻的 80MHz，射频上分开、基带拼成 160 用——5GHz 频谱碎，连续 160MHz 不好找）。

带宽HT/VHT 子载波数HE 子载波数理论吞吐×噪声底
20 MHz56/52 数据2421×基准 (-101 dBm @ 20MHz)
40 MHz108484~2×+3 dB
80 MHz234996~4×+6 dB

绑定不是免费的：三笔账

第一笔，灵敏度账（第 4 课）：带宽翻倍 → 噪声底 +3dB → 相同 SNR（信噪比）下可用 MCS（调制与编码方案）降一档。绑宽信道在远距离反而更慢——这是"我家 160MHz 怎么不如 80MHz"的头号原因。

第二笔，CCA（信道空闲评估）账（第 5 课）：发 80MHz 帧要求主 20 + 辅 20 + 辅 40 + 辅 60 全部空闲。邻居越多、越宽的信道越难等到"全家空闲"——密集部署里 160MHz 的实际信道利用率常常惨不忍睹。

第三笔，频谱账：5GHz 总共也就两个不重叠的 160MHz。相邻两家 AP（接入点）都用 160 → 同信道复用 → 互相压 CCA。企业部署普遍用 20/40MHz 做频率规划，家宽才敢开 160。

主信道位置也是部署变量：同一个 80MHz（如 ch36-48），主信道可以放在 ch36 也可以放在 ch44。相邻 AP（接入点）用相同 80MHz 但不同主 20MHz，能让各自的老设备/管理流量错开——这是企业频率规划的常规手法。

④ Wi-Fi 6 的解法：Preamble Puncturing

绑定最痛的是"辅信道有一个忙就全废"。802.11ax 给了破局手段：

传统 (11ac): 80MHz 传输要求全部 4 个 20MHz 空闲 ch36 ch40 ch44 ch48 ────── ────── ┌───── ────── 闲 闲 │忙(邻居AP) 闲 ↑ 整个 80MHz 退避! 3/4 的频谱白白闲着 Preamble Puncturing (11ax): ch36 ch40 ch44 ch48 ────── ────── ╳───── ────── 用 用 打洞 用 → 发 60MHz, 在前导码里声明"44 被打洞" → 接收方知道这段是干扰, 信道估计时绕开它

Preamble Puncturing（前导码打洞）：发送端在 HE 前导码（HE-SIG-A 的带宽/打洞字段）里声明"哪些 20/40MHz 段被打洞不用"，其余照常 OFDMA（正交频分多址）发送。接收方做信道估计时跳过洞，等于在忙频谱里见缝插针。Wi-Fi 7 (802.11be) 进一步把它扩展成更细粒度的 20MHz 打洞。这和 BSS Color（基本服务集着色，第 15 课）是一对：BSS Color 解决"听见了要不要退避"，打洞解决"退不掉的洞能不能绕开"。

⑤ 6GHz：Wi-Fi 6E 的新大陆

2020 年 FCC 开放 6GHz（5.925–7.125GHz，共 1200MHz）给免许可业务，Wi-Fi 6E/7 专用。它把本课所有痛点一次解决了一大半：

  • 频谱大：比 2.4G + 5G 之和还多，能塞下 7 个互不重叠的 160MHz——绑定不再是稀缺品。
  • 没有老设备：法规只许 HE (Wi-Fi 6) 及以上协议进入，不存在 11b/g/n 拖累，无需 20/40 共存机制。
  • 无需 DFS 等待（标准功率模式仍要 AFC（自动频率协调）查数据库，但不是雷达检测那套）。
  • 信令简化：不需要兼容旧前导码，发现/绑定流程更干净（用新的 Neighbor Report（邻居报告）/ Fast Initial Link Setup 机制）。

代价：6GHz 穿墙衰减更大（频率越高越像光），实际覆盖半径比 5GHz 还小一圈——大频谱 + 小覆盖，6GHz 注定是同室高吞吐专用频段。

对驱动栈：信道上下文落代码哪里

对驱动重要 / For Driver Stack

信道绑定和频谱管理在 Linux 栈里的落点：

  • cfg80211 regulatory：频段/信道/功率的法规数据库（CRDA / Linux 内置 regdb），DFS（动态频率选择）状态机也在这层。固件工程师移植时要对齐固件的信道表和内核法规域——两边不一致是经典 bug（固件能发 ch144，内核说 NO_IR，连不上）。
  • mac80211 channel context (chanctx)：每个在用的"信道+带宽+主信道位置"是一个 chanctx，AP（接入点）/STA（站点）加入对应 context。带宽切换（20↔40↔80）= 重构 chanctx + 通知固件切射频。多信道并发（如一个 2.4G + 一个 5G）= 多 chanctx + 时分切射频（MCC）。
  • 主辅信道协商：AP 在 Beacon（信标帧）的 HT/VHT Operation IE（信息元素）里通告带宽和辅信道位置；STA 驱动读它配置射频。抓包看 Beacon IE 是排查"为什么只跑 20MHz"的第一步。
  • DFS/CAC：AP 模式选到 DFS 信道要先 CAC（信道可用性检查，内核有 CAC 定时器、雷达检测回调 ieee80211_radar_detected）；雷达触发后整网换信道，所有 STA 跟着 Beacon 找新家。
  • 常见 bug：主信道被邻居占满导致吞吐塌方（辅信道闲也用不上）；带宽能力位声明错（STA 声明 160 但射频只支持 80）；DFS 信道雷达误报（微波炉/蓝牙脉冲被当雷达）频繁跳信道。

自检：信道绑定吃透了吗

这课的钉子：带宽是绑出来的

学完这课，你脑子里应该有：

  1. 频谱地图：2.4G（3 个不重叠信道，别绑 40）、5G（20+ 信道，DFS 要让雷达）、6G（1200MHz 新大陆，只有 Wi-Fi 6+ 能进）
  2. 信道绑定：40/80/160 = 主 20MHz + 逐级递归的辅信道；信令永远在主信道；绑定发送要求全带宽空闲
  3. 三笔账：噪声底 +3dB/倍频、CCA 全家必须闲、频谱规划变挤——宽信道只在 SNR 富余 + 邻居少时划算
  4. Preamble Puncturing：11ax 起可在前导码声明打洞，绕开忙频段见缝插针；与 BSS Color 是一对
  5. 驱动落点：cfg80211 法规/DFS、mac80211 chanctx、Beacon（信标帧）里 HT/VHT Operation IE 的带宽协商

你现在能做的：

  • 解释"为什么我家 160MHz 反而不如 80MHz 快"（噪声底 + CCA 两笔账）
  • 看 Beacon 的 Operation IE 推出这个 BSS（基本服务集）的带宽和主信道位置
  • 排查"STA 只跑 20MHz"：辅信道忙？老设备触发共存？能力位没开？
  • 理解 DFS 信道为什么 AP 上电要等一分钟（CAC）
