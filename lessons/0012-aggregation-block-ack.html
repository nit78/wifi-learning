帧聚合 / Block ACK —— 吞吐的命脉

到这里进入「提速」阶段（路线图第 8 步）。前 11 课讲的是"怎么连上、怎么加密、怎么分优先级"——基础机制。这课讲 802.11n 引入、现代 Wi-Fi 必备的两套提速机制：帧聚合（一次发一大坨）和 Block ACK (块确认)（一次确认一大批）。它俩是天作之合，一起把 Wi-Fi 从"百兆"推进到"千兆"。

这课对你做驱动的落点很硬核——聚合和 Block ACK 是吞吐优化的主战场。tx 路径的队列调度、rx 路径的重组（reorder）、Block ACK 会话的状态机，都是固件工程师最常调性能的地方。

支点：为什么要聚合

本课支点 / Core Insight

第 5 课讲过 CSMA/CA：每发一个帧都要 DIFS + 退避 + 帧本体 + SIFS + ACK。这套固定开销（DIFS+backoff+SIFS+ACK ≈ 几十到几百 μs）是每个帧都要付的"过路费"。

问题来了：如果把一个 1500 字节的 IP 包拆成 100 个小帧发，过路费要付 100 次；如果拼成 1 个大帧发，只付 1 次。聚合的本质：把"过路费"分摊到更多数据上，提升有效吞吐。

另一个痛点：每个帧一个 ACK，ACK 本身也是帧（带 SIFS + 帧本体）。发 100 个帧 = 100 个 ACK 往返。Block ACK 的本质：用一次确认替代 100 次确认。

这两套机制是 802.11n（Wi-Fi 4, 2009）引入的，是 Wi-Fi 从 54 Mbps 跃升到 600 Mbps 的关键之一。802.11ac/ax/be 全部继承并强化。

① 先理清：MSDU vs MPDU

聚合的两种方式，区别在于在哪一层拼。要先分清两个数据单元：

单元是什么有没有 MAC 头
MSDU (MAC 业务数据单元) 上层交给 MAC 的载荷（≈ 一个 IP 包） 还没有
MPDU (MAC 协议数据单元) 完整的 802.11 帧（MSDU + MAC 头 + FCS） 已经有

记住这条线：MSDU 是"原料"，MPDU 是"封装好的成品"。聚合可以在原料阶段拼（A-MSDU），也可以在成品阶段拼（A-MPDU）。

② A-MSDU：原料阶段拼，共享一个头

A-MSDU (Aggregate MSDU, 聚合 MSDU) 把多个 MSDU 拼成一个大载荷，共享一个 MAC 头。帧结构：

A-MSDU 帧结构: ┌─────────┬──────────────────────────────────────┬─────┐ │ MAC Header │ MSDU₁ │ MSDU₂ │ MSDU₃ │ ... │ MSDUₙ │ FCS │ │ (1 个) │ 每个 MSDU: DA(6B) + SA(6B) + Length(2B) + 数据 + padding │ │ └─────────┴──────────────────────────────────────┴─────┘ ↑ 所有 MSDU 共用外面那一个 MAC 头 + 一个 FCS 最大 3839 或 7935 字节

优势：开销最小——一个 MAC 头管多个包，效率最高。在干净信道下吞吐最好。

致命劣势：整个 A-MSDU 只有一个 FCS。任何一个 bit 错，整个帧 CRC 失败 → 整个 A-MSDU 重传。错一个 bit 赔整批数据。在噪声信道下性能崩塌。

③ A-MPDU：成品阶段拼，每个保留自己的头

A-MPDU (Aggregate MPDU, 聚合 MPDU) 把多个已封装好的 MPDU 拼成一个大帧，每个 MPDU 保留自己的 MAC 头和 FCS，前面加一个 4 字节的 MPDU Delimiter (定界符)：

A-MPDU 帧结构: ┌────┬─────────────────┬────┬─────────────────┬────┬─────────────────┬─────┐ │Dlm│MAC Hdr│MPDU₁ 数据│FCS│Dlm│MAC Hdr│MPDU₂ 数据│FCS│Dlm│MAC Hdr│MPDU₃ 数据│FCS│ ... │ └────┴─────────────────┴────┴─────────────────┴────┴─────────────────┴─────┘ ↑ ↑ ↑ 4B 定界符 4B 定界符 4B 定界符 每个 MPDU 自己的 MAC 头 + 自己的 FCS 802.11n: ≤65535B / 64 个 MPDU 802.11ac: 超 1MB（Max A-MPDU Length Exponent）

关键设计：MPDU Delimiter。这 4 字节标记"下一个 MPDU 多长、从哪开始"。作用：如果某个 MPDU 的 FCS 错了，接收方能靠 Delimiter 跳到下一个 MPDU 边界，不至于整个 A-MPDU 报废。这是 A-MPDU 选择重传能力的物理基础。

A-MSDU vs A-MPDU 一句话区别

A-MSDU：拼原料，一个头管全部，错一赔全部。
A-MPDU：拼成品，每个保留头+FCS+Delimiter，错了能挑出来重传。

现代 Wi-Fi（802.11n/ac/ax）主流只用 A-MPDU。A-MSDU 在 802.11ac 的 VHT PHY 弃用，因为它"错一赔全部"的脆弱性在高吞吐场景下太吃亏。A-MPDU + Block ACK 是黄金组合。

④ 对比表：两种聚合的取舍

维度 A-MSDU A-MPDU
聚合层次 MAC 头之前（原料） MAC 头之后（成品）
MAC 头数 1 个共享 每个 MPDU 自己一个
最大尺寸 3839 / 7935 B 65535 B (n) / 超 1MB (ac)
开销 小（一个头） 略大（每 MPDU 一个头）
错误恢复 弱（错一赔全部） 强（Delimiter + Block ACK 选择重传）
ACK 方式 单个 ACK Block ACK
现代 Wi-Fi 基本不用 主流
还有"两级聚合"（Two-level Aggregation）：A-MSDU 套在 A-MPDU 里——理论上最高效（A-MSDU 的低开销 + A-MPDU 的鲁棒性），但实现复杂，实际产品几乎不用。知道有这么个东西就行。

⑤ Block ACK：一次确认一大批

A-MPDU 发出去一坨，怎么确认？普通 ACK 一个帧一个 ACK 不现实（64 个 MPDU 要 64 个 ACK）。Block ACK (块确认) 用一个 Block Ack 帧携带位图（bitmap），记录这一批 MPDU 各自收没收到：

普通 ACK 流程 (旧, 慢): 发 MPDU₁ → ACK 发 MPDU₂ → ACK 发 MPDU₃ → ACK ... (N 个帧 = N 个 ACK 往返) Block ACK 流程 (现代, 快): 发 A-MPDU (含 MPDU₁..MPDU₆₄) 发 BAR (块确认请求, 带起始序列号) 收 Block Ack 位图: 1101110111... (每位对应一个 MPDU 收没收到) 只重传 没收到 的 MPDU (位图为 0 的那些)

Block ACK 的位图每一位对应一个序列号——1=收到、0=没收到。发送方看位图，只重传 0 的那些。这就是"选择重传"，比 A-MSDU 的"错一赔全部"高效得多。位图大小也限制了 A-MPDU 最多 64 个 MPDU（802.11n）。

⑥ Block ACK 会话：有状态，要先建

Block ACK 不是无状态的，用之前要建立会话（BA Session）。三步：

阶段帧作用
① 建立 ADDBA Request → ADDBA Response 协商 TID、buffer 大小、Immediate/Delayed 策略、超时
② 数据传输 A-MPDU → BAR → Block Ack 会话期间持续用 Block ACK，发送方按位图选择重传
③ 拆除 DELBA 任意一方发，释放会话资源（流量结束/超时/异常）

会话按 TID 建立——每个 AC 一个独立 BA 会话。回想第 11 课：语音走 AC_VO，视频走 AC_VI，它们各有自己的 Block ACK 会话。这也是为什么 Block ACK 只配合 QoS Data 帧（第 6 课讲过 QoS Data 帧带 TID）——没有 TID 就没法分会话。

Immediate vs Delayed Block ACK

Block ACK 两种响应时机：

  • Immediate BA (立即块确认)：收到 BAR 后 SIFS 内立即回 Block Ack。日常几乎都用这个。
  • Delayed BA (延迟块确认)：先 ACK BAR，过段时间再回 Block Ack（接收方需要时间处理时用）。极少见。

记一条就够：现代 Wi-Fi 默认 Immediate，Delayed 当背景了解。

⑦ 和 TXOP 的协同（回看第 11 课）

第 11 课讲 EDCA 的 TXOP：「抢到信道后能连续发多久」。聚合和 Block ACK 是怎么用满 TXOP 的工具：

  • 没有聚合：TXOP 时间内逐个帧发，每帧一个 ACK，过路费付很多次。
  • 有聚合：TXOP 时间内发一个大 A-MPDU（塞几十个 MPDU），一个 Block ACK 一次确认。过路费只付一次，分摊到几十个帧上。

所以高优先级 AC（AC_VO/AC_VI）的 TXOP 配额（1.5/3 ms）就是给聚合腾出连续发送窗口——窗口越大，能塞的 MPDU 越多，吞吐越高。这是 EDCA + 聚合 + Block ACK 三者的协同设计。

对驱动栈：聚合落代码哪里

对驱动重要 / For Driver Stack

聚合和 Block ACK 是吞吐优化的主战场，代码分布：

  • tx 聚合路径：驱动/固件把同一 TID 同一接收方的多个 MPDU 在硬件队列里聚合成 A-MPDU。聚合时机（什么时候凑够一批发出去）、最大 MPDU 数、最大尺寸——都是可调参数（叫 aggregation threshold / a-mpdu limit）。调不好要么吞吐低（聚合不够），要么延迟高（聚合过头）。
  • rx 重组（reorder）：A-MPDU 收到后要拆开，而且 Block ACK 选择重传会导致乱序（MPDU 5 重传后才到，但 MPDU 6 已经到了）。驱动要维护一个重组缓冲区，按序列号排好序再上交上层。这是 rx 路径最复杂的一块。
  • Block ACK 会话管理：ADDBA/DELBA 帧的收发、位图的维护、超时处理。SoftMAC 在 mac80211 的 agg-rx.c / agg-tx.c；FullMAC 在固件里。
  • 调试：tx 吞吐低 → 检查聚合是否启用（iw dev wlan0 station dump 看 tx bitrate 和聚合统计）；rx 乱序/丢包 → 检查重组缓冲区大小和 BA 会话状态。Wireshark 抓包能看到 A-MPDU 边界和 Block ACK 位图。
  • 常见 bug：①聚合尺寸超芯片限制导致硬件错误；②重组缓冲区溢出丢帧；③BA 会话建立失败导致退化为普通 ACK（吞吐腰斩）；④TID 映射错导致聚合到错误队列。

自检：聚合和 Block ACK 吃透了吗

这课的钉子：聚合 + Block ACK 是吞吐命脉

学完这课，你脑子里应该有提速的两件套：

  1. 聚合：把过路费（DIFS+backoff+ACK）分摊到更多数据上。A-MSDU 共享头（错一赔全部，已弃用）；A-MPDU 各自头+Delimiter（选择重传，主流）。
  2. Block ACK：用位图一次确认一批，配 A-MPDU 实现选择重传。会话按 TID 建（ADDBA/DELBA），只配 QoS Data 帧。

协同关系：EDCA 的 TXOP（第 11 课）给聚合腾连续发送窗口 → 聚合塞满窗口 → Block ACK 一次确认。三件套一起把 Wi-Fi 推进千兆。

你现在能做的：

  • 看到抓包里的 A-MPDU，按 Delimiter 拆出每个 MPDU
  • 理解为什么 A-MSDU 被弃用（错一赔全部 vs 选择重传）
  • 解释 Block ACK 会话为什么按 TID 建（每个 AC 独立）
  • 定位吞吐低：检查聚合是否启用、BA 会话是否建成功
  • 定位 rx 乱序：检查重组缓冲区和 Block ACK 位图处理
