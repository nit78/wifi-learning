MIMO 基础 —— 多天线到底在干嘛

这是课程最难的部分，也是 Wi-Fi 5→6 的分水岭。前 12 课讲的 PHY 都是"单天线怎么收发"，这课开始讲"多根天线怎么协作"。MIMO (Multiple-Input Multiple-Output, 多入多出) 是 802.11n 引入、Wi-Fi 4/5/6/7 全部依赖的 PHY 基石——没有它就没有千兆 Wi-Fi。

这课先打地基：多天线到底有几种用法、各自解决什么问题。下节课讲 MU-MIMO + OFDMA（Wi-Fi 6 核心），再下节讲 BSS Color。这三课是 PHY 深水区的"三连"，啃下来你就具备 Wi-Fi 6 固件工程师的 PHY 知识地图。

支点：多天线的两条路线

本课支点 / Core Insight

多根天线能干两件相反取舍的事，记住这对立：

  • ① 空间复用 (Spatial Multiplexing)：多天线同时传不同的数据流 → 提吞吐。天线多=流多=带宽翻倍。
  • ② 分集 (Diversity)：多天线传同一数据的冗余副本 → 提可靠性/距离。天线多=副本多=信号更稳更远。

同样的多天线硬件，要吞吐还是要稳定，二选一（或动态切换）。这是 MIMO 所有变种的根本取舍。

桥梁 / From BT & sub-GHz

蓝牙和大部分 sub-GHz 设备是单天线（BLE 天线分集是切换式的接收分集，不是真 MIMO）。你之前没接触过"多天线同时传不同数据"——这是 Wi-Fi/蜂窝才有的高级 PHY。但"用冗余换可靠性"的思路你熟悉：sub-GHz 的 FEC/扩频就是单天线版的"分集"。MIMO 把这个思路搬到空间维度。

① 空间复用：吞吐怎么翻倍的

核心问题：同样的频段、同样的时间，怎么塞更多数据？ 答案：用多天线在空间维度开多条并行通道。

单流 (SISO, 单天线): 发 1 根天线 ═══ 数据流 A ═══▶ 收 1 根天线 吞吐 = 1 × 单流速率 2×2 MIMO 空间复用 (2 流): 发 天线1 ═══ 数据流 A ═══▶ 收 天线1 发 天线2 ═══ 数据流 B ═══▶ 收 天线2 同频同时, 两个独立数据流 吞吐 = 2 × 单流速率 (翻倍!) 3×3 MIMO (3 流): 吞吐 = 3 × 单流速率 4×4 MIMO (4 流): 吞吐 = 4 × 单流速率 关键约束: 空间流数 ≤ min(发天线数, 收天线数) → 链路两端都要多天线, 取小的一边

关键认知：空间流数受链路两端天线数的"短板"限制。AP 有 8 根天线，手机只有 2 根，链路最多 2 流——手机是瓶颈。这就是为什么旗舰手机做 2×2 MIMO（两条空间流），而路由器做 4×4 或 8×8（多天线服务多个手机）。

标准最大空间流典型设备
802.11n (Wi-Fi 4)4 流路由器 3×3、手机 1-2 流
802.11ac (Wi-Fi 5)8 流路由器 4×4、手机 2 流
802.11ax (Wi-Fi 6)8 流路由器 8×8、手机 2 流
802.11be (Wi-Fi 7)16 流路由器多链路、手机 2 流

这是 SU-MIMO (Single-User MIMO, 单用户 MIMO)——所有空间流都发给同一个 STA。802.11n 只有 SU-MIMO。MU-MIMO（多用户，多个 STA 各占部分流）是 802.11ac Wave 2 才有，下节课讲。

② 分集：用冗余换可靠性

同一套多天线硬件，不传不同数据，改成传同一数据的多个副本——某个副本因多径衰落没了，还有别的副本兜底。这叫分集。分集不增吞吐，增可靠性、距离、抗衰落。

分集 (传同一数据的副本): 发 天线1 ═══ 数据 A 的副本① ═══▶ 收 发 天线2 ═══ 数据 A 的副本② ═══▶ 收 两个副本走不同路径, 某条衰落了另一条还在 接收端合并 → 信号更稳, 但吞吐不增 (传的是同一份数据) 对比空间复用 (传不同数据): 发 天线1 ═══ 数据 A ═══▶ 收 发 天线2 ═══ 数据 B ═══▶ 收 两份独立数据 → 吞吐翻倍, 但任一条衰落就丢数据

什么时候用分集而不是空间复用：信号差（远距离、多径严重、SNR 低）时。空间复用要求 SNR 足够高才能解出多流；SNR 差时多流解不开，反而退回分集保证基本连通。驱动 rate adaptation 算法会在两者间动态切——SNR 好上多流，SNR 差退分集/单流。

分集又分发射端和接收端两种，下面分别讲。

③ STBC：发射端分集（盲发冗余）

STBC (Space-Time Block Coding, 空时块编码) 是发射端分集技术，代表作是 Alamouti 码。原理：把同一数据用正交编码模式从多根天线发冗余副本，接收端靠正交性把它们分开再合并。

STBC 的关键特点
  • 不需接收方反馈 CSI（盲发）——发射端不知道信道什么样，靠编码的正交性保证可解
  • 代价：吞吐约减半——冗余占了一半"流资源"，本来能传 2 流的现在只传 1 流的数据
  • 用途：SNR 差时保距离/可靠性。比如远距离 STA 或多径严重的环境
  • 802.11n/ac 可选，不是所有芯片都实现

直觉：STBC 像"用两根天线说两遍同一句话，说的方法还正交，听话人能区分两遍并合并"。代价是说话慢了一半（同样时间传的信息少一半）。

④ MRC：接收端分集（标配）

MRC (Maximal Ratio Combining, 最大比合并) 是接收端分集。接收机有多根天线，收到同一信号的多个副本（每个副本经过不同路径、SNR 不同），MRC 按各路 SNR 加权相干合并——SNR 高的路权重大，低的权重小，合并后总 SNR 最大化。

MRC 的关键特点
  • 纯接收端 DSP——发射端不知道，不需反馈，不需协议支持
  • 不减吞吐——接收端合并是"免费"的增益，不影响发了几流
  • 802.11n/ac 标准，多天线接收机的"标配"
  • 类比：你做 sub-GHz 时如果用过天线切换分集，MRC 是更强的版本——不是切换选最好的，而是全部加权合并

⑤ 波束成形：把能量对准你

前面三种（空间复用/STBC/MRC）都不需要知道信道细节。波束成形 (Transmit Beamforming, TxBF) 不一样——它需要知道信道状态，然后加权对齐多天线信号，让它们在目标接收方处相干叠加增强。

无波束成形 (能量四散): 发 天线1 ──┐ 发 天线2 ──┤ 各发各的, 能量在空间四散 发 天线3 ──┤ 接收方 只收到其中一部分 发 天线4 ──┘ 有波束成形 (能量对准): 发 天线1 ──加权 w1──┐ 发 天线2 ──加权 w2──┤ 按信道加权, 信号在接收方处 发 天线3 ──加权 w3──┤ 相干叠加增强 (阵列增益) 发 天线4 ──加权 w4──┘ ▶ 接收方信号变强

类比：你做 sub-GHz 时如果用过定向天线，波束成形是电子版的定向天线——不用物理转动，靠多天线加权在软件/基带里"转向"。能量集中到目标方向，等于等效增益提升。

波束成形的关键特点
  • 需接收方反馈 CSI（Channel State Information, 信道状态信息）——发射端必须知道信道才能加权
  • 不减吞吐（增益是"免费"的 SNR 提升，只是前置有开销）
  • 增益大——SNR 提升几 dB，能拉开 MCS 等级，间接提吞吐
  • 代价：要探测信道（sounding），有协议开销和复杂度

⑥ Sounding：怎么拿到 CSI

波束成形的前提是发射方知道信道。怎么知道？靠 Sounding (信道探测)：

BeamFormer (发, 想做波束成形) BeamFormee (收, 要测信道) │ │ │ ① 发 NDP (Null Data Packet, 空数据包) │ │ ────────────────────────────────────────▶ │ 已知内容的"探测帧" │ │ 收方测每个子载波的信道响应 │ │ │ ② 反馈 CSI (压缩 V 矩阵) │ │ ◀──────────────────────────────────────── │ 把信道信息发回发方 │ │ │ 现在 BeamFormer 知道信道了 │ │ → 加权发数据, 实现波束成形 │

NDP (Null Data Packet, 空数据包) 是内容已知的探测帧——接收方拿收到的信号和已知内容对比，反推出每个子载波的信道响应（幅度+相位）。802.11ac 用 VHT NDP，802.11ax 用 HE NDP。Sounding 是波束成形的前置步骤，也是协议开销来源——信道变化快时要反复探测，开销吃掉一部分增益。

⑦ 显式 vs 隐式反馈：CSI 怎么传回来

CSI 从 BeamFormee 传回 BeamFormer 有两种方式：

方式怎么做优劣支持
显式反馈 接收方测完信道后直接把 CSI 发回（压缩 V 矩阵） 准，但有反馈帧开销 802.11n + 802.11ac（只用这个）
隐式反馈 利用信道互易性：TDD 系统上下行同频，发射方从上行信道推下行 省反馈开销，但 RF 链不一致要校准 (calibration)，不准 802.11n 支持，802.11ac 弃用

信道互易性 (Channel Reciprocity)：Wi-Fi 是 TDD（时分双工），上下行用同一频段不同时间，理论上信道对称。但实际 RF 链（功放、低噪放、天线）的收发特性不一致，要校准补偿。802.11ac 觉得校准麻烦又不准，干脆只用显式——多花点反馈开销换准确性。这是 802.11ac 相对 802.11n 的简化。

四种技术对比总表

技术在哪端要反馈 CSI?吞吐影响用途
空间复用 发+收 否 ↑↑ 翻倍 提吞吐（SNR 好时）
STBC 发 否（盲发） ↓ 减半 保可靠性/距离（SNR 差）
MRC 收 否 不减 接收端标配，提 SNR
波束成形 发 要（sounding） 不减（+前置开销） 提 SNR（SNR 好时增益大）
怎么记

两条问题决定用哪个：

  • "要吞吐还是要稳定?" → 吞吐走空间复用，稳定走 STBC/MRC
  • "能不能拿到 CSI?" → 能拿到走波束成形（增益大），拿不到走 STBC/MRC（盲）

实际系统动态组合：SNR 好时空间复用+波束成形榨干吞吐；SNR 差时退到 STBC/MRC 保连通。rate adaptation 算法实时切换。

对驱动栈：MIMO 落代码哪里

对驱动重要 / For Driver Stack

MIMO 大部分在硬件/固件里做，驱动层看到的接口：

  • 天线数 / 空间流数：芯片能力（capability），驱动注册时向 mac80211 声明（ieee80211_hw 的 max_rx_chains/max_tx_chains）。决定能做几流。
  • rate adaptation：决定当前用几流、什么调制（MCS）。SoftMAC 用 minstrel / minstrel_ht；FullMAC 在固件里。SNR 好上多流，差退单流。
  • 波束成形 sounding：触发 NDP 交换、维护 CSI。这部分固件主导，驱动看到的是"波束成形已激活/失效"事件。
  • 抓包看不到内部：MIMO 的空间流在 PHY 层，monitor mode 抓的是合并后的帧，看不到"这是几流"。但 VHT/HE PPDU 头里有空间流数字段，Wireshark 能读。
  • 调试：吞吐低 → iw dev wlan0 station dump 看 tx bitrate 和 tx bitrate flags（会显示几流、什么调制）。距离近吞吐上不去 → 检查波束成形/sounding 是否正常、天线数配置是否对。

自检：MIMO 基础吃透了吗

这课的钉子：MIMO 的两条路线四种技术

学完这课，你脑子里应该有 MIMO 的决策树：

  1. 要吞吐还是要稳定? 吞吐→空间复用；稳定→分集
  2. 分集在哪端? 发射端→STBC；接收端→MRC
  3. 能拿到 CSI? 能→波束成形（增益大）；不能→STBC/MRC（盲）

还有两个事实：空间流 ≤ min(收发天线数)；802.11ac 弃隐式波束成形只用显式。

你现在能做的：

  • 看手机规格 "2×2 MIMO" 知道是 2 空间流
  • 解释为什么 AP 多天线但手机是瓶颈（短板原理）
  • 区分 STBC（发射分集）和 MRC（接收分集）
  • 理解波束成形为什么要 sounding（拿 CSI）
  • 用 iw station dump 看当前几流什么调制

下一课：MU-MIMO + OFDMA（Wi-Fi 6 核心）

MIMO 基础打完，第 14 课进 MU-MIMO + OFDMA——这是 Wi-Fi 6 PHY 的真正核心：

  • MU-MIMO（802.11ac Wave 2 / 11ax）：AP 的多空间流分给不同 STA，同时服务多设备
  • OFDMA（802.11ax 独有）：把子载波分组（RU）分给不同 STA，AP 一次下行同时发多设备、上行多 STA 同时发

这俩是 Wi-Fi 6「高密度场景」（多设备、IoT）的核心，也是你做 Wi-Fi 6 固件绕不开的 PHY 特性。
