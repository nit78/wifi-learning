调试实战 —— 把不可见变可见

前 19 课讲的帧格式、握手、聚合、速率控制——全是"协议说应该这样"。这课给你一套工具，把"应该"变成"亲眼看见"：第 6 课的帧结构在 Wireshark（网络协议分析器）里逐字节展开，第 9 课的四次握手逐帧对时序，第 18 课的 MCS（调制与编码方案）选择在 rc_stats（速率控制统计）里逐档显示。这是从"学过"到"能排查问题"的分水岭，也是面试里"你怎么定位 Wi-Fi 问题"的标准答案。

支点：三层可见性，对应三个世界

本课支点 / Core Insight

调试的本质是把不可见变可见。按"你想看哪个世界"选工具：

  • 配置态（栈认为链路怎么样）：iw（无线配置工具）—— 一句话拿出现状
  • 空口态（电波里真实发生了什么）：monitor（监听）模式 + tcpdump/Wireshark —— 帧级证据
  • 驱动态（硬件和驱动内部）：debugfs（内核调试文件系统）+ dmesg（内核日志）—— 内部状态

三个世界经常互相矛盾（栈说已连接、空口全是重传、驱动说固件报错）——矛盾本身就是线索。

① 配置态：iw 全家桶

iw 是 nl80211（Netlink 用户态接口，第 19 课那条用户态通道）的命令行客户端，取代古老的 iwconfig。先分清两个对象：phy（物理射频设备，对应 wiphy）和 dev（网络接口，wlan0 是 phy 上开出来的一个"角色"）。

# 现状一句话 —— 链路诊断的起点 iw dev wlan0 link # 连到哪个 SSID（服务集标识）/ 信道 / 信号多强 iw dev wlan0 station dump # 每 STA（站点）一行, 字段全是前几课的知识: # signal: -52 dBm（分贝毫瓦） → 第 4 课 RSSI（接收信号强度指示） # tx bitrate: 866.7 MBit/s VHT-MCS 9 80MHz → 第 13/15/18 课 速率+带宽+MCS # tx retries / tx failed: → 第 18 课 重传统计 # tx power, authorized, connected time ... iw dev wlan0 scan # 扫描: 邻居 AP（接入点）列表 + 各自信道/信号/能力 iw dev wlan0 get power_save # 省电状态 → 第 8 课 PS（省电）模式 iw reg get # 当前法规域 → 第 16 课 5GHz 信道可用性 iw phy # phy 能力全集: 支持的 band（频段）/MCS/接口组合

最常用的是 station dump：把链路质量（signal）、当前速率（bitrate/MCS）、可靠性（retries/failed）三样一次看清。注意它只显示"已连接"的对端——扫描列表里没有它就是没关联上，先往第 7 课的流程方向查。

② 空口态：monitor 模式 + 抓包

正常模式下网卡只收"发给自己"的帧。要看整个电波里的一切（别人的握手、邻居的 Beacon（信标帧）、重传、竞争），要开 monitor（监听）模式——把网卡变成"旁听者"：

# 加一个监听接口（不动 wlan0，原接口还能正常用） iw phy phy0 interface add mon0 type monitor ip link set mon0 up # 监听必须钉在某个信道上（不能边扫描边监听） iw dev mon0 set channel 36 HT20 # 信道 36, 20MHz（兆赫兹）带宽; 可选 HT40-/HE80… # 抓 10 秒存文件, 回 Wireshark 分析 tcpdump -i mon0 -w cap.pcap

抓到的每个帧前面都有一段 radiotap（无线捕获元数据头）——不是 802.11 帧的一部分，而是驱动附加的"这帧怎么收来的"元数据（第 19 课 RX 路径填的那些字段的用户态镜像）：信号强度（dBm_antsignal）、信道、速率字段（MCS/VHT/HE-MU）。比如"这帧是 HE（高效 Wi-Fi，Wi-Fi 6） MCS 11、信号 -71 dBm"——速率自适应问题（第 18 课）的现场证据就在这。

实践提醒 / Practice Notes

① 不是所有网卡/驱动都支持 monitor（FullMAC（全硬件介质访问控制）芯片常受限）；② 打了硬件加密的帧抓到也是密文——EAPOL（局域网上的 EAP）握手帧没加密所以永远可读（第 9 课），数据帧在 monitor 下通常只见密文；③ 你的笔记本 Wi-Fi 多半是 macOS/Windows 管的，真要练手建议一块 USB（通用串行总线）的 monitor 友好网卡（如 ath9k/rt2x00 系）跑 Linux。

③ Wireshark：过滤器实战（前 18 课的复习现场）

Wireshark 的显示过滤器（display filter）用第 6 课的字段名直接过滤。常用清单（背下来）：

过滤表达式含义对应课程
wlan.fc.type == 0 / 1 / 2管理帧 / 控制帧 / 数据帧（Frame Control（帧控制）字段）第 6 课
wlan.fc.type_subtype == 0x0008Beacon（信标帧）第 5/7 课
wlan.fc.type_subtype == 0x0000 / 0x0001Association Request（关联请求）/ Response（关联响应）——看 status code（状态码）第 7 课
wlan.fc.type_subtype == 0x000cDeauthentication（解除认证）——"为什么被踢"的答案在这帧里第 7 课
eapol四次握手 M1–M4（Key（密钥）消息逐帧可见）第 9/10 课
wlan.addr == AA:BB:CC:DD:EE:FF只看某个 MAC（介质访问控制地址）的收发—
wlan.fc.retry == 1只看重传帧——竞争/干扰强度的直接指标第 5/18 课
radiotap.dbm_antsignal < -75信号弱于 -75 dBm 的帧第 4 课

组合拳示例：wlan.fc.type == 0 && wlan.addr == 你的手机MAC + 时间排序 = 完整还原第 7 课的关联流程（Probe（探测）→ Auth（认证）→ Assoc（关联））+ 第 9 课的 M1–M4。每个前几课画在 ASCII 图里的帧，都能这样亲手抓一遍——这是全课程最值得做的一次实验。

④ 驱动态：debugfs（内核调试文件系统）

第 18 课提过的 rc_stats 就住在这。路径结构（冒号在 shell 里要转义）：

/sys/kernel/debug/ieee80211/phy0/ ├── netdev:wlan0/ │ └── stations/<对端MAC>/ # 每个已关联站点一个目录 │ ├── rc_stats # 速率控制统计: 每档 MCS 的 │ │ # 成功率/期望吞吐/EWMA/采样次数 → 第 18 课 │ ├── agg_status # 每 TID 聚合会话状态 → 第 12 课 │ └── flags ... └── mt76/ 或 ath9k/ ... # 驱动自己的调试文件（芯片专属）

三个前提，缺一个目录就不在：① 内核开了 CONFIG_MAC80211_DEBUGFS；② 只对已连接的站点生成；③ FullMAC（全硬件介质访问控制）芯片速率控制在固件里，往往没有 rc_stats——这本身就是判断"这块卡是 SoftMAC（软件介质访问控制）还是 FullMAC"的快捷方法。

配套两件：dmesg（内核日志）看驱动/固件的主动报告（固件崩溃、超时、掉线原因码）；动态调试（dynamic debug）按模块开详细日志：echo 'module mt76 +p' > /sys/kernel/debug/dynamic_debug/control——排查驱动问题时把日志开到最细，结束记得关回去。

⑤ 三个故障案例走查（把工具串成流程）

案例 A: 连不上 / 关联失败 iw scan 能看到 AP（接入点）吗? ├─ 看不到 → 信号/信道/法规域问题 (iw reg get, 换位置) └─ 看得到 → dmesg 驱动报错? └─ 干净 → monitor 抓管理帧, 按 time（时间）排: Auth（认证）没回? → 密码/加密版本不匹配 (第 9 课 WPA2/WPA3) Assoc Resp（关联响应）status code? → 满员/能力不匹配 (第 7 课) M1 后无 M2? → 密码错 (PMK 派生失败) 关联成功但立刻 Deauth（解除认证）→ 看 Deauth 里的 reason code 案例 B: 能连但吞吐低 station dump 三看: signal 好 + bitrate 低 → 看 rc_stats: 卡在哪一档? sample 了吗? (第 18 课) tx retries 高 → 抓包看 retry 帧: 碰撞多还是信号差 (第 5 课) 带宽只有 20MHz → 第 16 课: 邻居占满辅信道, 绑定被降级 别忘了查省电: get power_save + AP（接入点）侧 DTIM（投递业务指示图）设置 (第 8 课) 案例 C: 信号差/频繁断连 station dump signal 走势 + scan 里邻居列表: 同信道邻居多 → 信道拥挤, 换信道 (第 3/16 课) 信号随位置骤降 → 路径损耗/障碍 (第 3 课 FSPL（自由空间路径损耗）) 断连时 Deauth reason + 是否在漫游? (第 17 课 802.11r/k/v 有没有生效)

注意每个案例的套路都一样：先用 iw 缩小范围 → 再用抓包/日志拿帧级证据 → 最后对应到某一课的原理解释。工具是三层的，思路是闭环的。

对驱动栈：工具背后是哪段代码

对驱动重要 / For Driver Stack

把第 19 课的代码地图和这课的工具对上——每个工具都是某段内核代码的用户态窗口：

  • iw → nl80211 消息 → cfg80211/mac80211：station dump 读的就是 sta_info.c（站点信息表）里的统计。
  • monitor 接口 → mac80211 在 RX（接收）路径复制一份帧给 monitor 接口（进入接收处理链之前的分发），radiotap 头由 ieee80211_add_rx_radiotap_header 拼装——你抓到的每个字节都能在 net/mac80211/rx.c 找到生成处。
  • rc_stats → 速率控制算法经 .add_sta_debugfs 回调挂上的 debugfs 文件（minstrel_ht 的 minstrel_ht_add_sta_debugfs，代码在 rc/rc80211_minstrel_debugfs.c）。
  • dmesg 驱动日志 → 驱动里 dev_err/dev_warn（设备错误/警告日志）；固件日志通常经 MCU（微控制器）消息通道转存——mt76 的 debugfs.c 里就有读固件日志的入口。

工程师的职业习惯：报 bug 时把这三样一起贴上——iw dev wlan0 station dump 输出、一段抓包、dmesg 时间线。有这三样，任何 Wi-Fi 工程师都能远程帮你。

自检：调试工具箱配齐了吗

这课的钉子：三层工具，一个闭环

学完这课，你脑子里应该有：

  1. 三层可见性：配置态（iw）→ 空口态（monitor + tcpdump/Wireshark）→ 驱动态（debugfs + dmesg）；三个世界矛盾时，矛盾就是线索
  2. iw 三板斧：link（链路现状）、scan（邻居环境）、station dump（signal/bitrate/retries 三要素）
  3. monitor + radiotap（无线捕获元数据头）：钉信道抓包，radiotap 给出每帧的信号/速率证据
  4. Wireshark 过滤器：type/subtype（帧类型）分管理/控制/数据，eapol 抓握手，retry（重传）位看竞争
  5. debugfs：rc_stats 看速率自适应现场；它的存在本身区分 SoftMAC（软件介质访问控制）/FullMAC（全硬件介质访问控制）
  6. 排查套路：iw 缩小范围 → 抓包/日志拿证据 → 对应课程原理解释；报 bug 必带三件套（station dump/抓包/dmesg）

你现在能做的：

  • 用 monitor 模式完整抓一次自己手机的关联 + 四次握手，对照第 7/9 课逐帧打勾
  • 用 wlan.fc.retry == 1 统计重传占比，感受不同时段的信道竞争
  • 找到自己网卡的 rc_stats（如果有），亲眼看 EWMA（指数加权滑动平均）和采样记录
  • 给自己定一条纪律：以后任何 Wi-Fi 问题，先跑 station dump 再说话
