Sounding/NDP 帧格式实战 —— 波束成形的协议入口

这是第 13 课波束成形/sounding（信道探测）的协议实战深入。前两节补充（sup-0003 矩阵、sup-0004 Alamouti）是"数学为什么"，这节是"协议怎么跑"——波束成形到底用哪些帧、字段装什么、抓包怎么读。这是三个补充里和你做协议栈工作最相关的一个。

第 13 课讲了 sounding 概念（发 NDP（空数据包） → 测信道 → 反馈 CSI（信道状态信息））。这课把它拆到帧级：NDPA、NDP、VHT Compressed Beamforming、BRP 这些帧各自长啥样、谁先发、字段含义。学完你能在 Wireshark 里读懂一整套 sounding 交换。

① 全景：一次 sounding 用到哪些帧

波束成形前必须先 sounding 拿 CSI。802.11ac 的显式 sounding 用一组帧完成：

BeamFormer (AP, 想做波束成形) BeamFormee 1 BeamFormee 2 │ │ │ │ ① VHT NDPA (通知: 马上来 NDP) │ │ │ ────────────────────────────────────▶│───────────────────▶│ 广播/单播 Action 帧 │ │ │ │ ② VHT NDP (空数据包, 已知内容) │ │ │ ───────────────────SIFS────────────▶│───────────────────▶│ 收方测信道 │ │ │ │ ③ VHT Compressed BF (CSI 反馈) │ │ │ ◀──────────────────SIFS────────────── │ │ STA1 先回 (NDPA 列表顺序) │ │ │ │ ④ BRP (Beamforming Report Poll) │ │ │ ───────────────────SIFS────────────▶│ │ 点名 STA2 回反馈 │ │ │ │ ⑤ VHT Compressed BF │ │ │ ◀──────────────────SIFS──────────────────────────────────── │ STA2 回 CSI │ │ │ │ 现在 AP 有所有 STA 的 CSI, 可以做 MU-MIMO 波束成形了 │

关键点：

  • NDPA 先行：NDP 不能直接发，要先发 NDPA 告诉接收方"准备好，NDP 马上来"——否则接收方不知道这个帧是来探测信道的。
  • SIFS 间隔：每对帧之间是 SIFS（16μs），保持交换紧凑不被打断。这是第 5 课 SIFS 作为"进行中对话"优先级的体现。
  • 多 STA 轮询：MU-MIMO（多用户 MIMO）场景下 AP（接入点）给多个 STA（站点）sounding，反馈按 NDPA 里的 STA 顺序逐个回，靠 BRP（Beamforming Report Poll，波束成形报告轮询）点名。

② NDPA 帧：sounding 的"开场通知"

NDPA (NDP Announcement, NDP 通告) 是个Action 管理帧，作用是通知"NDP 要来了，以下是该测信道的 STA 列表"：

VHT NDPA 帧布局: ┌──────────┬──────────┬─────────┬─────────┬──────────────────────┐ │ Frame Ctrl │ Duration │ Addr1=RA │ Addr2=TA │ Category + Action │ └──────────┴──────────┴─────────┴─────────┴──────────────────────┘ │ ┌───────────────────────┴───────────────────────┐ │ Sounding Dialogue Token (1B, 序号) │ ├───────────────────────────────────────────────┤ │ STA Info 1: AID12 (12b) + Feedback Type (1b) + Nc (3b) │ ├───────────────────────────────────────────────┤ │ STA Info 2: ... (多 STA 时有多个) │ └───────────────────────────────────────────────┘ RA: 单 STA 时是该 STA 地址; 多 STA 时是广播 TA: BeamFormer (AP) 的地址 STA Info 列表的【顺序】决定后面 CSI 反馈的顺序

STA Info 子字段是 NDPA 的核心，每个要 sounding 的 STA 一个：

子字段位数含义
AID1212 bitSTA 的 AID（关联标识，第 7 课），标识"该你测信道"
Feedback Type1 bit0 = SU（单用户反馈），1 = MU（多用户反馈）
Nc Index3 bit steering 矩阵的最大列数 Nc − 1（波束成形维度）

STA Info 的顺序很重要：它决定了谁先回 CSI。NDPA 里 STA Info 1 对应的 STA 在 NDP 后第一个回 Compressed BF，STA Info 2 由 AP 用 BRP 点名回。这是协议级的"反馈调度"。

③ NDP 帧：已知内容的"探测帧"

NDP (Null Data Packet, 空数据包) 在 NDPA 后 SIFS（短帧间间隔）发出。它没有数据载荷（所以叫 Null），但有完整的 PHY 前导码（preamble）——前导码的训练字段（training fields）内容双方已知。

NDP 为什么能测信道

接收方知道 NDP 前导码"应该是什么样"，收到后拿实际信号和"应有信号"对比，反推出每个子载波的信道响应（幅度+相位）。这就是 CSI。原理和 OFDM 的训练序列（第 2 课）一样——已知信号过未知信道，从输出推信道。

NDP 在 802.11ac 叫 VHT NDP，在 802.11ax 叫 HE NDP。它们的 PHY 头标识自己"这是 NDP"（VHT 靠 VHT Signal A 字段的组合值——Group ID=63、N_STS=0——来标识，没有专门的"NDP 位"），让接收方进 sounding 处理路径而非数据接收路径。

④ VHT Compressed Beamforming：CSI 怎么传回来

接收方测完信道后，要把 CSI 反馈给 AP（接入点）。原始 CSI 数据量大（每个子载波×每个天线对的复数），802.11ac 用压缩格式 VHT Compressed Beamforming——传的是压缩后的 V 矩阵（sup-0003 讲的 SVD（奇异值分解）里那个 V，发端预编码权重）。

VHT Compressed Beamforming 帧: ┌──────────┬──────────┬─────────────────────────────────┐ │ MAC Hdr │ Category │ VHT MIMO Control + Compressed BF │ │(Action) │ (VHT) │ (压缩后的 V 矩阵反馈) │ └──────────┴──────────┴─────────────────────────────────┘ VHT MIMO Control: 标识这是给谁的反馈、什么粒度 Compressed BF: 实际的 V 矩阵角度数据 (Givens 旋转参数化)

注意：反馈的是 V 矩阵（发端预编码权重），不是原始 H。这样 AP 拿到 V 直接就能用，不用自己再做 SVD。这是"显式反馈"的精髓——接收方做了重活（测 H + 算 SVD），把结果 V 交给 AP。

压缩用的是 Givens 旋转参数化——把酉矩阵 V 表示成一组角度，比存复数矩阵省空间。这是协议设计在"准确性 vs 开销"上的权衡。

⑤ BRP：多 STA 场景的"点名"帧

多 STA sounding 时（MU-MIMO 前置），多个 STA 要回 CSI，但不能同时回（会碰撞）。协议用 BRP (Beamforming Report Poll, 波束成形报告轮询) 逐个点名：

  • NDPA 里 STA Info 列表的第一个 STA 在 NDP 后自动回（不用点名）。
  • 第二个及以后的 STA（站点），AP（接入点）发 BRP 帧逐个点名："STA2，该你回了" → STA2 回 Compressed BF → AP 再 BRP STA3...

这避免了多 STA 同时反馈的碰撞，代价是 sounding 时长变长（STA 越多越久）。这是 MU-MIMO 开销的来源之一——为什么 MU-MIMO 的 sounding 比 SU-MIMO（单用户 MIMO）重。

⑥ SU vs MU Sounding：帧序列对比

场景帧序列开销
SU 波束成形（单 STA） NDPA → NDP → Compressed BF 小（3 帧）
MU 波束成形（多 STA） NDPA → NDP → BF(STA1) → BRP → BF(STA2) → BRP → BF(STA3)... 大（每 STA 多 2 帧）

这就是为什么 802.11ac 的 MU-MIMO 实际增益常被打折——sounding 开销吃掉了一部分波束成形增益。STA 越多、移动越快（信道变化快要反复 sounding），开销越明显。这也是 802.11ax 引入新的 HE sounding 优化（更紧凑、支持 OFDMA（正交频分多址）并行 sounding）的动机。

对驱动栈：sounding 协议落代码哪里

对驱动重要 / For Driver Stack

sounding 在协议栈里的落点（这节最贴你的工作）：

  • NDPA/NDP 收发：AP（接入点）模式要构造并发 NDPA + NDP；STA（站点）模式要识别 NDPA、进 sounding 路径、测信道、构造 Compressed BF 回发。SoftMAC（软件 MAC）在 mac80211 + 固件配合；FullMAC（全 MAC）主要在固件。
  • BRP 状态机：多 STA sounding 是个小型状态机（NDPA → 等 NDP → 等 STA1 反馈 → 发 BRP 点 STA2 → ...）。你要维护"当前轮到谁、超时没回怎么办"。BRP 超时是常见 bug——STA 没在 SIFS（短帧间间隔）内回反馈，AP 要重试或放弃该 STA。
  • CSI/V 矩阵存储：每个 STA 的 V 矩阵要存起来用于后续波束成形。信道变化后要重新 sounding 更新。缓存过期策略（多久重 sounding）是性能/准确性权衡的关键参数。
  • 调试：Wireshark monitor mode 能看到 NDPA/NDP/Compressed BF/BRP 这套帧序列。波束成形不生效 → 先抓包看 sounding 是否完成；吞吐低 → 看 sounding 频率（是不是太频繁吃开销）。iw dev wlan0 station dump 里有 tx bitrate flags 显示是否激活了 TxBF（发射波束成形）。
  • 常见 bug：①STA 不支持显式反馈（能力位没协商）导致 AP 发不出 NDPA；②SIFS 超时导致 BRP 链断裂；③CSI 压缩解压不对导致 V 矩阵错、波束对错方向；④移动场景下 sounding 过期未更新。

一句话总结

波束成形的 sounding 是一组管理帧的协作交换：NDPA 通知 → NDP 探测（已知内容测信道）→ Compressed BF 反馈 V 矩阵（压缩的发端权重）→ 多 STA 时 BRP 点名轮询。每个帧带具体字段（STA Info 的 AID/Feedback Type/Nc），抓包能逐字段读。

这套协议是波束成形/MU-MIMO 落到协议栈的实体——sup-0003 讲的"V 矩阵从哪来"，答案就在这组的 Compressed BF 帧里。你做驱动调试波束成形，90% 时间在调这套 sounding 帧序列。

三个补充课的关系

这三个补充课构成 MIMO 数学/协议的完整闭环：

  1. sup-0003 矩阵解耦：为什么两流不干扰（SVD 把 H 拆成正交模式，V/U 预编码后编码）
