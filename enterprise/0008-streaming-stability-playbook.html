拉流与稳定性排查实战 —— 把两门课串成一本排查手册

这是你开这门课的原始目标："排查 Wi-Fi 使用情况下的拉流异常和稳定性异常"。前面 21 + 8 课攒的全部知识在这课收口——先解剖"视频拉流"到底是什么样的流量，再把"卡"分成三种病、把"掉线"理成一条原因链，最后给你一张症状 → 原因 → 工具 → 课次的总速查表。

支点：卡顿不是一种病，是三种病

本课支点 / Core Insight

视频卡顿在 Wi-Fi 层面只有三种机理：吞吐不足（饥饿）——平均速率低于视频码率，缓冲只出不进；抖动（心律不齐）——平均够但忽快忽慢，抖动缓冲被瞬间打穿；瞬断（休克）——链路直接断开，缓冲清零重连。先分型，再排查——三种病的病因谱完全不同，混着查只会晕。

① 应用层视角：拉流到底是什么流量

ABR(自适应码率)拉流: HLS/DASH(基于 HTTP 的流媒体协议) 视频被切成 2-10 秒的分段(chunk), 客户端循环"下载一段→播一段" 同一内容备有多种码率档 → 播放器按缓冲水位升降档: 水位涨 → 升档(更清晰) 水位跌 → 降档(保命) jitter buffer(抖动缓冲) 播放器前端的蓄水池: 提前存几秒, 吸收网络忽快忽慢 水位被瞬时波动打穿 → 卡; 干涸 → 转圈重缓冲 码率结构: VBR(可变码率)/GOP(画面组) 每个 GOP 一个 I 帧(全量, 尺寸尖峰) + 追踪帧(小) → 瞬时带宽需求 = 平均码率的 2-3 倍(I 帧尖峰) 落到 Wi-Fi 上是什么 周期性突发大下载 + 少量上行确认 —— 本质是 BE(尽力而为)大流量 除非流量带 DSCP(差分服务代码点)标记被映进 VI(视频)队列 (主课 11)

② 三种卡顿的病因谱（每条线都挂回课次）

病型现象特征病因谱（按概率）
A 吞吐不足 画质自动降档、长时间转圈、缓冲水位持续下降 信号差 MCS（调制与编码方案）低（企课 2/5 → 主课 18）｜晚高峰容量不足（企课 5 airtime（空口时间）账）｜速率自适应卡低档（主课 18 rc_stats）｜聚合建不起来（主课 12）｜2.4GHz 拥挤（企课 5）
B 抖动 画质还行但周期性一顿一顿、延迟波动大 空口竞争/重传波动（企课 6 抓包数 retry（重传））｜省电唤醒迟滞（主课 8）｜漫游扫描让链路周期性走神（主课 17）｜速率自适应震荡（主课 18）｜缓冲设置过小（应用侧）
C 瞬断 直接断开、重连、从零重缓冲 漫游切换（主课 17，企课 5 重叠设计）｜deauth（解除认证）泛洪（企课 7）｜省电超时被 AP 踢（主课 8）｜固件崩溃/复位（企课 4 查 dmesg（内核日志）复位原因）｜PoE（以太网供电）欠压重启（企课 4，负载相关）

③ 分诊流程：第一问永远是三要素

卡顿分诊 (发生时立即采证): iw dev wlan0 station dump │ ├─ signal 差 (<-75dBm(分贝毫瓦)) │ → 覆盖/环境线: 走场画分布 (企课 6 迷你验证) │ 死点? 人体/障碍 (企课 2)? 小区边缘拉流 (企课 5)? │ ├─ signal 好 + bitrate 低 │ → 速率线: rc_stats(速率控制统计) 看卡在哪档 (主课 18) │ sample(试探) 有没有? 被限速? 聚合没建起来 (主课 12)? │ ├─ signal 好 + bitrate 好 + retries 高 │ → 干扰线: 抓包 retry 比例 (企课 6) │ 邻居信道占用 (企课 5)? 频谱仪找非 Wi-Fi 干扰 (企课 6)? │ └─ 三要素全好但就是卡 → 边界测试: iperf3 打点 iperf3 也差 → Wi-Fi 链路仍有问题 (深挖聚合/驱动) iperf3 正常 → 不是 Wi-Fi! 上应用/服务器/出口带宽 掉线分诊: 掉线时刻的四个证据 抓包: 有无 deauth? 节奏? (企课 7) dmesg: 复位原因? (企课 4) 漫游: 掉线前后换 AP 了吗? (主课 17) 省电: 模式与超时? (主课 8)

⑤ 三个案例走查（把流程跑一遍）

案例 A: 手机拿在手里走动, 每 30 秒卡一次 分诊: 卡时三要素 → signal 好, 但 station dump 显示换了 AP 定性: B 抖动 + C 瞬断混合 = 漫游切换 (sticky/扫描耗时) 处方: 802.11k/v 开启+切换阈值调优 / 重叠区重设计 ← 主课 17 + 企课 5 案例 B: 每晚 8 点全家视频全员卡, 白天正常 分诊: 高峰时 retry 高 + 邻居列表暴增 (整栋楼同时在拉流) 定性: A 吞吐不足 = 容量失败 (同信道邻居把空口时间分光) 处方: 5/6GHz 引导 + 信道重规划 + 低速率禁用 ← 企课 5/6 案例 C: 摄像头(电池版)每小时掉线一次, 其他设备正常 分诊: 掉线无 deauth; dmesg 干净; 该设备省电模式最深 定性: C 瞬断 = 省电睡眠过头, AP 保活超时把它踢了 处方: Listen Interval(监听间隔)调小 / TWT(目标唤醒时间)协商修正 ← 主课 8

⑥ 测量工具箱（一表收全）

工具测什么关键用法

iperf3吞吐（TCP）/ 抖动+丢包（UDP）iperf3 -c 服务器 测吞吐；iperf3 -c -u -b 50M 看 jitter/loss——Wi-Fi 与应用层的边界测试

这课的钉子：三病 · 三要素 · 三件套

  1. 三病分型：吞吐不足（饥饿）/ 抖动（心律不齐）/ 瞬断（休克）——先分型再排查，病因谱不同
